# STEP 01 · Cowork로 MasterDB 만들기

여러분이 갖고 온 것은 두 가지입니다.

1. **화면 스케치 HTML** — 사전 과제에서 "이런 서비스면 좋겠다"고 그려 본 예시 화면
2. **데이터 파일들** — 데이터로 사용할 정리됐거나 안 됐거나 한 실제 업무 파일들
   (엑셀, 워드, 메시지 대화를 긁어온 텍스트, 이미지가 섞인 엑셀 등 무엇이든 괜찮습니다. 또한 없어도 됩니다.)

이 시간에는 **데이터 파일들**을 컴퓨터가 다룰 수 있는 표로 만들어봅니다.
이 결과물을 **MasterDB**라고 부르겠습니다.

---

## 시작 전 : 화면 스케치의 위치

화면 스케치는 "이상적인 모습"을 그린 그림이라, 지금 가진 데이터로는 만들 수 없는
기능이 들어 있는 경우가 대부분입니다.

> [!NOTE]
> 각 데이터들의 생성 날짜가 없는데 화면에서 데이터 생성 날짜 확인을 위한 캘린더를 만들어낼 수는 없습니다.

그래서 스케치도 함께 첨부하되, **데이터 구조의 기준은 어디까지나 실제 데이터**입니다.
스케치는 "무엇을 하고 싶은지"를 보여주는 참고 자료로만 씁니다.

순서가 중요합니다 :
```text
1. 데이터를 먼저 바로 세우고 → 2. 그 데이터로 가능한 화면을 만든다
(화면을 먼저 정해 놓고 데이터를 화면에 끼워 맞추면, 화면에 표현할 데이터[원본]를 신뢰하기 어렵습니다)
```

아래 프롬프트에 이 원칙이 이미 들어 있으니, 아래 프롬프트를 그대로 복사해서 쓰면 됩니다.

---

## MasterDB 작업 규칙

규칙이 좀 많아 보이지만, 전부 **"나중에 프로그램이 이 표를 읽을 수 있는가"** 하나에서 나온 것들입니다.
아래 프롬프트에 이미 전부 들어 있으니 외울 필요는 없습니다. 결과물을 볼 때 눈으로 확인하는 용도입니다.

### 표를 어떻게 나누어야 할까?

| 규칙 | 왜 그래야 하나요 |
|---|---|
| 시트(탭) 1개 = 표 1개 | 한 시트에 표를 두세 개 붙여 놓으면, 어디부터 어디까지가 한 표인지 알 수 없습니다 |
| 1행은 열 이름, 2행부터 데이터 | 첫 줄은 무조건 제목 줄로 읽습니다. 첫 줄에 데이터가 들어 있으면 그 값이 열 이름이 되어 버립니다 |
| 한 줄 = 한 건 (소계·합계 줄 없음) | 대분류 줄, 소계 줄, 명세 줄이 한 표에 섞여 있으면 몇 건인지 셀 방법이 없습니다. 소계는 기록이 아니라 계산 결과라서, 합계를 낼 때 한 번 더 더해집니다 |
| 한 칸에는 값 하나만 | `강판 120, 봉재 30`이 한 칸에 들어 있으면 강판만 골라 볼 수가 없습니다. 두 줄로 나눠 적습니다 |
| 옆으로 늘리지 말고 아래로 쌓기 | `1월│2월│…│12월`처럼 옆으로 펼쳐 두면 내년에 열을 또 만들어야 합니다. `날짜│자재│수량` 세 열로 아래로 쌓으면 몇 년 치가 쌓여도 열은 그대로입니다 |
| 반복되는 이름은 별도 시트로 | 거래처 이름이 100줄에 걸쳐 적혀 있으면, 이름이 바뀔 때 100군데를 다 고쳐야 합니다. 따로 모아 두면 한 군데만 고치면 됩니다 |
| 표마다 첫 열은 번호(ID), 연결도 번호로 | 이름으로 이어 두면 `대성철강`이 `대성철강㈜`로 바뀌는 순간 연결이 전부 끊깁니다. `C001` 같은 번호는 이름이 바뀌어도 그대로입니다. 나중에 화면에서 "이 줄 수정"을 누를 때도 이 번호로 그 줄을 찾습니다 |

### 값을 어떻게 적어야 할까?

| 규칙 | 왜 그래야 하나요 |
|---|---|
| 날짜는 `2026-09-01` 형식 | `9/1`, `9월 1일`은 날짜가 아니라 그냥 글자로 취급됩니다. 날짜순 정렬이나 "이번 달만 보기"가 안 됩니다 |
| 금액·수량은 숫자만 (`50000`) | `50,000원`은 숫자가 아니라 글자입니다. 합계도 평균도 계산되지 않습니다. 단위가 필요하면 `단위` 열을 따로 만듭니다 |
| 값이 없으면 빈칸 그대로 | `-`, `없음`, `N/A`, `미정`이 섞이면 그것들도 각각 하나의 값으로 셉니다. "비어 있다"는 뜻은 빈칸 하나로 통일합니다 |
| 같은 대상은 한 가지 표기로 | `㈜대성철강`·`대성철강`·`대성`은 사람에겐 같은 회사지만, 거래처 세 곳으로 집계됩니다 |
| 0으로 시작하는 번호·코드는 글자로 | 사번 `0012`를 숫자로 저장하면 `12`가 되고, 품번 `3-1`은 3월 1일로 바뀝니다. 더하고 뺄 일이 없는 번호는 글자로 저장합니다 |
| 병합·색칠·서식·수식은 데이터가 아님 | 노란색으로 칠해서 "긴급"을 표시해도 색은 읽히지 않습니다. `긴급`이라고 글자로 적어야 합니다. 합친 셀은 합쳐진 자리의 값이 비고, 수식은 다른 곳으로 옮기면 깨집니다. 이미지 속 숫자도 글자로 옮겨 적습니다 |

표의 개수나 행 수에는 제한이 없습니다. **실제 업무 구조상 필요한 만큼** 나눕니다.
시간이 조금 더 걸리더라도, 데이터 엔지니어가 설계하듯 제대로 나누는 것이 목표입니다.

## 옵션 1 : 데이터 파일을 가져온 경우

1. Claude Desktop 앱에서 **Cowork** 새 대화를 엽니다.
2. 데이터 파일들과 **화면 스케치 HTML**을 전부 첨부합니다.
3. 아래 프롬프트를 **그대로 복사해서** 붙여넣습니다.

```
첨부한 파일들은 내 업무 데이터야. 형식이 제각각이고 정리도 안 되어 있어.
(엑셀일 수도, 워드일 수도, 메시지 대화를 긁어온 텍스트일 수도, 이미지가 섞인 엑셀일 수도 있어.)

이걸 실무 데이터 엔지니어가 설계하듯 제대로 정규화해서,
프로그램이 읽을 수 있는 MasterDB 엑셀 파일로 만들어줘.
이 파일은 곧 Google Sheets로 옮겨서, 내가 만들 웹 화면이 직접 읽고 쓸 원본 데이터가 될 거야.

[표 구조]
- 시트(탭) 1개 = 표 1개. 1행은 열 이름, 2행부터 데이터.
  표 위에 제목 줄이나 설명 줄을 넣지 마
- 한 표의 모든 행은 같은 종류의 사건 하나를 뜻해야 해.
  대분류 행, 소계 행, 합계 행처럼 성격이 다른 행이 섞여 있으면 없애거나 표를 나눠줘
- 한 칸에는 값 하나만. "강판 120, 봉재 30"처럼 한 칸에 여러 값이 있으면 행을 나눠줘
- 기간이나 항목이 가로로 펼쳐진 표(1월|2월|…|12월, 제품A|제품B|제품C)는 세로로 바꿔줘.
  예: [날짜 | 제품 | 수량]. 데이터가 늘어날 때 열이 늘어나는 구조면 안 돼
- 표의 개수는 제한 없어. 실제 업무 구조가 요구하는 만큼 나눠줘

[열과 연결]
- 모든 표의 첫 열은 그 행을 가리키는 고유 ID야. 규칙 있게 만들어줘 (입고기록은 R0001, 거래처는 C0001 식으로)
- 반복해서 나오는 이름(고객명, 제품명, 거래처 등)은 별도 시트로 분리하고,
  기록 시트에서는 이름 대신 그 시트의 ID로 연결해줘
- 열 이름은 한 표 안에서 중복 없이, 줄바꿈 없이 짧게.
  "수량(kg)"처럼 단위가 붙어 있으면 [수량] [단위] 두 열로 나눠줘
- 시트(탭) 이름은 공백·특수문자·이모지 없이 짧게

[값의 형식]
- 날짜는 YYYY-MM-DD, 시각까지 있으면 YYYY-MM-DD HH:MM, 월 단위 값이면 YYYY-MM
- 금액·수량은 숫자만. 쉼표나 "원", "개", "kg" 같은 단위를 붙이지 마
- 값이 없으면 빈칸으로 둬. "-", "없음", "N/A", "미정" 같은 걸로 채우지 마
- 같은 대상인데 표기가 흔들리는 이름은 하나로 통일해줘
  (㈜대성철강 / 대성철강 / 대성 → 하나로). 무엇을 무엇으로 합쳤는지 목록으로 보여줘
- 상태·구분처럼 정해진 값이 반복되는 열은 표기를 하나로 통일하고
  (완료 / O / Y / done 이 섞여 있으면 하나로), 그 열에 쓴 값의 목록을 알려줘
- 코드·전화번호·사번처럼 0으로 시작하거나 하이픈이 들어간 값(0012, 010-1234-5678, 3-1)은
  숫자가 아니라 텍스트로 저장해줘. 앞자리 0이 사라지거나 날짜로 바뀌면 안 돼
- 셀에 수식을 넣지 마. 계산 결과 말고 값 자체를 넣어줘
- 병합 셀, 색칠, 테두리, 글꼴 같은 서식은 전부 빼고 값만 남겨줘
- 이미지 안이나 문장 속에 들어 있는 정보도 값으로 뽑아서 표에 넣어줘

[출처와 확인 필요]
- 기록 시트마다 [출처] 열을 하나 두고, 그 행이 어느 첨부 파일에서 왔는지 적어줘
- 확실하지 않은 값은 추측해서 채우지 말고 비워 둬.
  그리고 "확인필요"라는 시트를 하나 만들어서
  [시트명 | 행ID | 열이름 | 왜 애매한지 | 내가 확인해줘야 할 것] 형태로 전부 모아줘

첨부한 HTML 파일은 내가 그려 본 예시 화면(UI)이야. 이건 참고 자료일 뿐이고,
데이터 구조 설계의 기준은 실제 데이터 파일들이야.
- 예시 화면에만 나오고 실제 데이터에는 근거가 없는 항목·기능은
  그대로 반영하지 말고, 나에게 "이 항목은 데이터가 없는데 어떻게 할까?"라고 물어봐.
- 예시 화면과 실제 데이터가 어긋나는 지점들을 정리해서 알려줘.

진행 순서:
1. 먼저 첨부 파일마다 어떤 정보가 들어 있는지 요약해서 알려줘.
2. 어떤 표와 열로 나눌지, 표끼리 어떤 ID로 연결되는지 제안하고, 왜 그렇게 나누는지 설명해줘.
3. 네가 판단하기 애매한 건 나에게 질문해줘. 한 번에 하나씩 물어봐.
4. 내 답을 반영해서 최종 MasterDB 엑셀 파일을 만들어줘.
5. 마지막으로 위 규격을 항목별로 하나씩 스스로 점검해서 통과/실패를 표로 알려줘.
   실패한 항목이 있으면 고치고 다시 점검해줘.
```

4. **Cowork가 질문하면 성실히 답합니다 (매우 중요).**
   파일에는 없고 여러분 머릿속에만 있는 정보(이 열이 무슨 뜻인지, 이 값은 왜 비어 있는지)가
   데이터의 품질을 결정합니다.
5. 완성된 엑셀 파일을 **다운로드**합니다.

## 옵션 2 : 데이터가 없는 경우 (새로 설계)

데이터는 없고, 완전히 새로 만들고자 하는 서비스를 설명하면 Cowork가 표를 설계해 줍니다.
화면 스케치 HTML을 첨부하고 시작하시면 됩니다. 단, 설계의 기준은 **말로 설명하는 실제 업무**입니다.

```
나는 지금부터 간단한 업무 관리 웹 서비스를 만들려고 해. 데이터는 아직 없어.
첨부한 HTML은 내가 그려 본 예시 화면(UI)인데, 참고 자료일 뿐이야.

내가 만들려는 것: (여기에 3~5줄로 설명. 예: "우리 공장에 들어오는 원자재
입고 기록을 관리하고 싶어. 언제, 어떤 자재가, 얼마나, 어느 거래처에서
들어왔는지 기록하고 나중에 거래처별로 조회하고 싶어.")

이걸 담을 MasterDB 엑셀 파일을 실무 데이터 엔지니어가 설계하듯 만들어줘.
이 파일은 곧 Google Sheets로 옮겨서, 내가 만들 웹 화면이 직접 읽고 쓸 원본 데이터가 될 거야.

[표 구조]
- 시트(탭) 1개 = 표 1개. 1행은 열 이름, 2행부터 데이터
- 한 표의 모든 행은 같은 종류의 사건 하나를 뜻해야 해. 소계 행이나 합계 행은 만들지 마
- 한 칸에는 값 하나만
- 기간이나 항목을 가로로 펼치지 마(1월|2월|…|12월 같은 구조 금지). 세로로 쌓아줘
- 표의 개수는 실제 업무 구조가 요구하는 만큼

[열과 연결]
- 모든 표의 첫 열은 고유 ID야. 규칙 있게 만들어줘 (R0001, C0001 식으로)
- 반복해서 나오는 이름은 별도 시트로 분리하고, 기록 시트에서는 그 시트의 ID로 연결해줘
- 열 이름은 중복 없이 짧게. 단위는 열 이름에 넣지 말고 별도 열로
- 시트(탭) 이름은 공백·특수문자 없이 짧게

[값의 형식]
- 날짜는 YYYY-MM-DD, 금액·수량은 숫자만 (단위 없이)
- 값이 없으면 빈칸. "-"나 "없음"으로 채우지 마
- 상태·구분 열은 쓸 값의 목록을 먼저 정하고 그 안에서만 써줘
- 코드·전화번호처럼 0으로 시작하거나 하이픈이 들어간 값은 텍스트로 저장해줘
- 수식·병합 셀·서식 없이 값만
- 연습용 예시 데이터를 표마다 20행씩 채워줘 (실제처럼 그럴듯하게)

진행 순서:
1. 필요한 표와 열, 표끼리의 ID 연결을 제안하고, 왜 그렇게 나눴는지 설명해줘.
   예시 화면에만 나오고 내 업무 설명에 근거가 없는 항목은 그대로 반영하지 말고 나에게 물어봐.
2. 애매한 건 나에게 한 번에 하나씩 질문해줘.
3. 내 답을 반영해서 최종 파일을 만들어줘.
4. 마지막으로 위 규격을 항목별로 점검해서 통과/실패를 표로 알려줘.
```

---

## ✅ 체크포인트

- [ ] 엑셀 파일이 1개 다운로드되어 있다
- [ ] 시트(탭)마다 표가 딱 하나씩이다
- [ ] 첫 줄이 열 이름이다
- [ ] 병합된 셀이 없다
- [ ] 반복되는 이름(고객·제품·거래처 등)이 별도 시트로 나뉘어 있다
- [ ] 표마다 첫 열이 ID 열이고, 기록 시트가 그 ID로 연결되어 있다
- [ ] 1월·2월처럼 가로로 펼쳐진 열이 남아 있지 않다
- [ ] `확인필요` 시트가 있고, 거기 적힌 것들을 한 번 훑어봤다

하나라도 어긋나면 Cowork에 이렇게 말하세요 :
> "규격을 다시 확인해줘. [어긋난 부분]이 규격과 달라. 고쳐서 다시 만들어줘."
